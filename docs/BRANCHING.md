# Git Branching Strategy (브랜치 관리 전략)

이 프로젝트는 안정성과 개발 유연성을 모두 확보하기 위해 다음과 같은 브랜치 분리(모듈화) 전략을 사용합니다.

## 1. 브랜치 구조

- **`main` (릴리즈 / 안정 버전)**
  - 가장 안정적이고 배포 준비가 완료된 코드만 올라갑니다.
  - 사용자가 실제 프로젝트에 쓸 수 있는 검증된 버전입니다.
  - 직접 커밋하지 않고, `dev` 브랜치에서 기능 검증이 끝나면 Pull Request(PR) 혹은 Merge를 통해 업데이트합니다.

- **`dev` (개발 / 테스트 / 실험실)**
  - 최신 기능 개발, 버그 수정, 새로운 모듈 테스트 등 모든 실험적인 작업이 이루어집니다.
  - 개발자가 일상적으로 코드를 푸시하고 빌드 테스트를 진행하는 메인 작업 공간입니다.
  - 현재 체크아웃되어 있는 브랜치입니다! 마음껏 코드를 수정하고 테스트하세요.

## 2. 작업 흐름 (Workflow)

1. **새로운 기능 개발 / 코드 수정**
   - 항상 `dev` 브랜치에서 작업합니다.
   - `git checkout dev`
   - 코드 작성 및 커밋 (`git commit -m "Add new feature"`)
   - `git push origin dev`

2. **안정화 및 배포 (릴리즈)**
   - `dev`에서 충분히 테스트되어 문제가 없다면 `main`으로 병합(Merge)합니다.
   - `git checkout main`
   - `git merge dev`
   - `git push origin main`
   - (선택) GitHub 페이지에서 `main` 브랜치를 기준으로 새 Release 태그(v1.0.0 등)를 생성합니다.
